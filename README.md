# desksaw — desktop pet for AwesomeWM

A physics-driven desktop pet: an articulated little creature that walks around
your desktop, falls off windows, bumps into them, gets flung when you drag it,
and picks itself back up. A Lua port of DeskSaw's character logic, built on
`simplephys`' physics engine.

## Files

```
~/.config/awesome/desksaw/
├── init.lua        Module API: per-screen actors, fixed-timestep drive timer
├── box.lua         Wibox, physics step, character AI, grab/throw, obstacles
├── skeleton.lua    Articulated renderer: bones + parts + Cairo drawing
├── pose.lua        Bone hierarchy, Godot Bone2D angles, two-bone IK solver
├── anim.lua        Keyframed clips (generated from the Godot scene)
├── physics.lua     Rigid-body physics (from simplephys)
├── sprite.lua      PNG loading helpers (from simplephys)
├── carve.lua       Rectangle subtraction (from simplephys)
├── preview.lua     Render a pose to PNG, offline  <-- validate before reloading
├── checkpose.lua   Numeric pose check (bbox per frame, no draw errors)
├── checkrig.lua    Rig check: IK targets reached, bone lengths constant
├── tools/
│   └── extract_anim.py   Regenerates anim.lua from scenes/sawianBase.tscn
└── README.md
```

## Architecture

The pet is **not** a baked image. It is the real skeleton from the DeskSaw Godot
scene, reimplemented in Lua in two layers:

### `pose.lua` — the rig (pure Lua, no cairo)

- **Bones** (`pose.BONES`) — hip → back → head, two 3-joint arm chains, two
  3-joint leg chains, plus a tail and the `ikNodes` frame. Positions/rotations
  are transcribed from `scenes/sawianBase.tscn`.
- **Two-bone IK** (`pose.IK_CHAINS`) — a direct port of `soup_two_bone_ik.gd`.
  The clip animates the IK *targets* (which live in the rotated `ikNodes`
  frame); the solver places each limb so its end lands on the target. Bend
  direction follows the scene's `flip_bend_direction` via
  `bend = (flip and -1 or 1)`.
- **Clips** (`anim.lua`) — hip position/rotation, the four IK targets and the
  tail rotation, keyframed. Generated by `tools/extract_anim.py`.

### `skeleton.lua` — the renderer (cairo/LGI)

- **Parts** (`skeleton.PARTS`) — each body part is a `Sprite2D` attached to a
  bone via a `RemoteTransform2D`. Draw order comes from the Godot scene (tail →
  back limbs → torso → front limbs → head → eye).
- Draws each part with `cr:transform()` on a matrix carrying the physics
  position, body angle, scale and facing, then paints the texture.
- **Opaque-art bounds** — the source PNGs are padded (the head is a 54×28
  canvas holding a 20×12 head). Bounds are computed from the tight opaque
  pixels, and the draw centres on the art rather than the canvas, so the
  physics box and the visible pet agree. This is what stopped the pet floating
  above (or clipping through) the floor.

### `box.lua` — the character

- Wander AI, lean from acceleration, landing crouch, ragdoll when flung
  sideways, pendulum grab/throw. Mirrors DeskSaw's `movement_handler.gd` /
  `live_body.gd` / `behavior.gd`.

Skeleton space is y-**down** (feet at y≈+6, hip at y≈−19). A single placement
matrix carries it to screen space.

## Character states

| State | When | Clip |
|---|---|---|
| `idle` | on the ground, not walking | `idleagain` |
| `moving` | `dir ~= 0` and under max speed | `moveF` |
| `jumping` | airborne, moving up | `jump` |
| `falling` | airborne, moving down | `fall` |
| `ragdoll` | horizontal speed over `ragdoll_speed` | (frozen, limp limbs) |

Ragdoll triggers on *horizontal* speed only (like DeskSaw), recovers when the
body settles on the ground for 0.7 s, or after 3.5 s as a failsafe.

## Integration

`rc.lua` loads it defensively — a load or init failure disables the pet and
leaves awesome running:

```lua
local desksaw = nil
do
    local ok, mod = pcall(require, "desksaw")
    if ok then desksaw = mod else print("[desksaw] disabled: " .. tostring(mod)) end
end

-- in the per-screen loop:
if desksaw then
    local ok, err = pcall(desksaw.init, s)
    if not ok then print("[desksaw] init failed: " .. tostring(err)) end
end
```

## Safety: validate offline before reloading

A draw error raised inside a wibox `shape` / `bgimage` callback runs in
AwesomeWM's C draw path and **cannot be caught from Lua**. It kills the window
manager, and with it the X session. This actually happened once during
development.

So the workflow is:

1. Edit the renderer.
2. Validate offline — this exercises the exact draw code the WM would:

   ```bash
   cd ~/.config/awesome
   luajit desksaw/checkrig.lua                          # IK + bone lengths
   luajit desksaw/checkpose.lua                         # no draw errors, per clip
   luajit desksaw/preview.lua /tmp/pose.png idleagain 0 0
   luajit desksaw/preview.lua /tmp/sheet.png --sheet    # all clips
   ```

3. Only then reload, with the module guarded so a failure degrades to "no pet":

   ```bash
   awesome-client 'for k in pairs(package.loaded) do
       if k:match("^desksaw") then package.loaded[k]=nil end end
     require("desksaw")'
   ```

Traps worth remembering:

- `cairo.Matrix` must be built from a **named-field table**
  (`cairo.Matrix{xx=,xy=,yx=,yy=,x0=,y0=}`). The six-positional-argument
  constructor segfaults.
- LuaJIT's `math.atan` takes `y/x`; it is **not** `atan2`. `pose.atan2` wraps
  the correct quadrant logic.
- `ffi` is a LuaJIT built-in, not a requireable module under Lua 5.4. The
  opaque-bounds scan degrades gracefully when it is unavailable.
- All render work is wrapped in `pcall` inside `box.lua`'s draw callbacks; the
  first failure disables pet rendering and prints once instead of taking the
  WM with it.

## Configuration

`desksaw.config` in `init.lua`:

```lua
sprite_scale   = 4      -- pixels per skeleton unit
fps            = 60
gravity        = 784    -- matches the scene's RigidBody2D gravity_scale = 0.8
maxspeed       = 240
ragdoll_speed  = 575    -- horizontal px/s that triggers going limp
sound_path     = ".../thudswoosh.ogg"
```

## Regenerating the animations

After changing the Godot scene:

```bash
python3 ~/.config/awesome/desksaw/tools/extract_anim.py
```

## Notes / known gaps

- The original DeskSaw Godot/C# project is located at `/home/tsuchinoko/desksaw-original`.
- `sit` and `laydown` clips exist and render, but the character never enters
  those states yet (DeskSaw's rest logic is not ported).
- No eye-state swapping yet (`skeleton.eye_texture` is fixed to
  `experimentEyeOpen`); the other eye PNGs are wired up and ready.
- `moveB` (walking backwards) exists but the walk always plays `moveF`.
- The physics box is the idle-pose bounding box, not a per-part compound
  collider like the original's Rapier bodies.
- `sprite.lua` / `carve.lua` are inherited from simplephys; `carve.lua` is
  unused by the current `box.lua`.
